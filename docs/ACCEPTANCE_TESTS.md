# P0 验收测试

下列用例是未来实现的行为验收标准，不是本轮已执行结果。每个用例应构造最小合成数据集，固定时钟、数据快照和规则版本；测试不得通过联网数据获得偶然成功。

| ID | 场景 | 预期结果 |
| --- | --- | --- |
| AT-001 | 严格模式读取一条缺少 `available_at` 的财务记录 | 抛出 `DataUnavailableError`；不会以报告期末替代 |
| AT-002 | 同一财务指标在之后被修订 | `as_of` 修订前返回旧版本，修订后返回新版本；历史回测不改变 |
| AT-003 | 日线 D 收盘后才可用，信号在 D 生成 | 最早执行会话为 `next_session(D)`，绝不在 D 成交 |
| AT-004 | 周三读取本周周线 | 严格择时拒绝未完成周；研究模式仅返回 `partial` 且不可生成交易信号 |
| AT-005 | 周五收盘后生成周线信号 | 最早执行为下一交易周首个可交易会话，不是周五收盘 |
| AT-006 | 当前指数/行业成分与历史不同 | 历史查询只包含当时有效且当时可得的成分，不使用当前名单 |
| AT-007 | 标的在回测期内 ST、改名或退市 | 主数据按有效期生效；股票池给出可追溯排除原因，代码复用不串数据 |
| AT-008 | 计划买入日停牌 | 不产生成交；订单状态按配置挂起/取消，并记录原因 |
| AT-009 | 涨停导致买入不可成交、跌停导致卖出不可成交 | 方向分别受限，不能以收盘价强行成交 |
| AT-010 | 除权除息日前后 | 信号序列按声明复权口径连续；成交/组合收益按原始价与公司行为正确核算 |
| AT-011 | `available_at` 早于实际 `ingested_at` | 严谨模式在 `ingested_at` 前不可读；报告记录延迟 |
| AT-012 | 原始载荷相同的采集批次重复运行 | 标准化数据幂等；血缘仍能定位两个运行批次或去重说明 |
| AT-013 | 全 A 等权序列出现缺失或成分覆盖不足 | 产生覆盖率告警；超过规则阈值时市场状态拒绝输出而非填零 |
| AT-014 | 连续普跌后首次反弹但未满足确认条件 | `cash_capable` 不提前恢复暴露；理由包含规则版本和观察窗口 |
| AT-015 | 全球代理在 A 股开盘时尚未收盘或节假日 | 依据明确时差规则使用上一可得观察值或标记缺失，不能读取未来收盘 |
| AT-016 | 期货会员排名输入 | 输出保留交易所、合约、会员、排名、公开字段、等级；不产生“机构净持仓”字段 |
| AT-017 | `cash_capable` 与 `always_invested` 对照回测 | 两组报告共享快照、费用、滑点、股票池和执行规则；均报告暴露、换手、成本、回撤与空仓天数 |
| AT-018 | 费用、税费、滑点为非零 | 成交、现金、净值和换手一致地计入版本化成本参数 |
| AT-019 | 相同代码版本、配置、快照和期间重复回测 | 订单、成交、净值、指标及审计哈希完全一致 |
| AT-020 | 日报构建输入存在非审计数据或数据质量告警 | 产物明确标注研究限制；严格发布策略可配置为阻断 |
| AT-021 | 发布目录包含 SQLite、原始载荷或凭据文件 | `StaticPublisher` 拒绝发布；只允许白名单静态文件 |
| AT-022 | 移动端日报 JSON | 通过 schema 校验，含 `as_of`、构建版本、数据截点、风险提示和证据等级，不含敏感配置 |

## 质量门禁

P0 合并前至少应满足：全部 AT-001 至 AT-012、AT-018 至 AT-021 通过；覆盖率、失败率与数据延迟有可观测日志；静态检查禁止策略层直接导入第三方数据 SDK 或 SQLite 实现；每一份回测输出都可关联到 `run_id`、`data_snapshot_id` 和规则版本。AT-013 至 AT-017、AT-022 可随相应模块合入，但其模块不得在标记通过前宣布可用于正式策略研究。
