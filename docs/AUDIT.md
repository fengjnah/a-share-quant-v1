## P0 审计发现

### P0-1：没有历史可得性模型，直接回测必然存在前视偏差

普通的“交易日期”不足以证明当时可以知道某个值。例如财报的报告期、公告时间和数据接口抓取时间不同；指数成分的当前名单也不能替代历史名单。所有进入研究、信号或回测的数据必须具有 `source`、`event_time`、`available_at`、`ingested_at` 四个字段，定义见 [DATA_CONTRACT.md](DATA_CONTRACT.md)。缺失 `available_at` 的记录不得作为严格回测输入。

### P0-2：行情可交易性需要单独建模

日线收盘价不是天然可成交价。停牌、退市、涨跌停、复牌、除权除息、最小交易单位、交易成本和滑点均会改变订单是否能执行与实际成交价格。回测引擎必须通过交易日历和可交易性数据决定执行，而不能只用 OHLCV 表的非空行。

### P0-3：周线和财务特征是高风险信号源

周线在周五收盘前不能使用当周最终收盘；周末或节假日生成的周线信号只能安排到下一可交易日。财务特征应以公告发布时间加保守缓冲后的 `available_at` 生效，不能以报告期末或当前数据接口中的修订值回填历史。

### P0-4：“机构净持仓”不能由不完整数据反推

期货交易所公开排名、会员持仓、机构公开报告和市场代理指标属于不同证据等级。系统必须记录字段来源、覆盖范围、发布日期及可验证性；没有能识别最终机构主体的公开字段时，不得输出或命名为“机构净持仓”。

### P0-5：运行边界应优先控制成本和风险

本地 PC 承担采集、SQLite、研究、回测和日报构建。AWS EC2 t3.micro 只通过 Nginx 只读发布已生成的 HTML/JSON；不存放凭据，不执行全市场扫描，不运行回测任务，也不连接真实交易账户。

## 审计建议的准入门槛

1. 未达到 [ACCEPTANCE_TESTS.md](ACCEPTANCE_TESTS.md) 的 P0 用例前，禁止将回测结果用于策略比较。
2. 未保存原始载荷、数据版本和时间戳的结果只可标为探索性研究，不可标为审计回测。
3. 每次回测必须输出配置、代码版本、数据快照范围、时间可得性策略和成本模型版本。
4. 所有模拟交易与真实交易适配器必须保持隔离；本轮及 P0 不实现真实交易适配器。
