# 模型路由与开发治理制度

版本：1.0；新增决策日期：2026-10-17；制定任务：TASK-GOV-001。实施状态见[项目状态](PROJECT_STATUS.md)。这是任务分配和审查规则，不是模型能力认证、价格表、运行时锁定器或已部署的 CI 门禁。

## 1. 分工与风险分类

默认选满足要求且经核验成本较低的模型完成 L 类工作，把高能力模型集中用于 H 类设计、关键正确性和阶段验收。L/H 是任务分配等级，不以品牌、名称、上下文长度或推理强度代替能力与风险判断。

| 类别 | 可分配范围 | 必须提供的依据 |
| --- | --- | --- |
| L：低成本优先 | 明确的文档维护、稳定接口下的字段映射、局部工具、已有契约的离线测试及不改变语义的小修复 | 边界和契约已确认；没有下表风险；模型实际可用、成本/预算依据明确；有确定的验收命令 |
| H：高能力优先 | 架构/契约设计、高风险实现、独立审查、阶段验收 | 确切模型与推理档位、相关代码能力/工具兼容性依据、可复现的正确性证据；H 本身不保证正确 |

出现以下任一风险直接进入 H，不累计等待普通批次：

- 数据库迁移、版本注册、唯一/外键/不可变约束、事务/回滚或连接生命周期变更。
- `event_time`、`available_at`、`observed_at`、`ingested_at`、`as_of`、历史版本选择、证券身份/有效期或缺失数据语义变更。
- 未来函数、历史成分/财务发布时间、复权/公司行为、信号与成交时点、停牌/涨跌停处理。
- 核心回测执行、订单/成交、费用滑点、现金/持仓/收益记账或可交易性逻辑。
- 数据真实性与来源认证边界、凭据/安全/生产运行边界、本制度及 AGENTS/override/模型路由配置变更。

风险按最终行为和累计 diff 判定。即使文件叫“文档”“测试”或“字段映射”，涉及这些语义也属于 H；不能拆成多个 L TASK、降低测试标准或更改标签规避。无法判断时先按 H 做范围/风险澄清。

## 2. 一个 TASK，一个模型和推理档位

每个 TASK 用[任务模板](tasks/TASK_TEMPLATE.md)建立记录；可放独立任务单、既有实施报告或 PR 的任务记录中，不强制为历史任务补造执行信息。必须在实现前填写：

| 必填项 | 可核验要求 |
| --- | --- |
| TASK ID、类型、目标与前置依赖 | 编号独立；implementation / review / acceptance 等类型明确；依赖 PR 的 head/base/状态及实际基线 SHA |
| 唯一执行模型 | 提供方/平台 + **一个具体模型 ID/可识别版本**；禁止候选列表、“任选”“自动”“Codex”或“高能力模型”作为执行值 |
| 固定推理强度 | 当前模型实际支持的一个档位；不支持此参数时写“不支持”并附官方或运行证据，不能用“默认”掩盖未知 |
| 核验来源与时间 | 运行元数据、宿主界面或用户对当前界面的确认；区分实际运行证据与计划配置，不能从全局配置推断当前会话 |
| L/H 等级与预算 | 风险理由、成本依据/核验时间、重试上限及预算；额度/实际费用未提供时写“未知”，不记为 0 或已节省 |
| 修改边界与验收 | 允许/禁止路径及行为、必读契约、可执行命令和预期断言、交付物、审查批次/独立审查 TASK |

任务开始报告确认实际读取 [AGENTS.md](../AGENTS.md)、本制度及相关契约，列出路径/版本、适用 G 编号、模型/档位和基线。元数据未齐时只做只读检查并请求缺失信息，不开始实现。不使用未核验的自动模型别名/fallback；如平台只能自动路由且无法确认唯一模型，任务标记阻断。

实现、补测试、运行测试、写文档和普通 diff 自检均由该唯一模型完成。确定性测试、lint、文件/Git 工具和资料搜索不算另一执行模型；**主动调用其他模型生成/修改实现、替任务作判断或形成正式审查结论**算混用，禁止通过 API、子代理、换角色提示或新线程规避。当前规则不授权委派；即使使用同型号子代理也应另立明确任务，不能把多个执行者伪记为单一执行。

需要更换模型或推理强度时，当前 TASK 保存现场并以 blocked/escalated 结案，不标记 completed；新 TASK 明确继承未完成目标、原任务/失败证据、基线与新的唯一模型。中断/压缩后恢复，先查实际文件、提交和已执行日志，保持原模型/档位；不得借恢复混用模型或重写已完成工作。已知供应商别名发生版本漂移时也停止并重新立项核对。

## 3. Agnes、DeepSeek 与 Codex 的建议用途

以下是候选使用方向，不是指定当前某型号的能力、价格或额度：

| 平台/提供方 | 建议用途 | 采用前核验 |
| --- | --- | --- |
| Agnes | 在实际可用型号通过项目小样本后，可选作 L 文档、稳定契约下的局部实现或测试任务 | 具体模型 ID、代码/工具调用、上下文、推理档位、数据外发边界、当前账单/限额；不能因品牌或旧对话称其必然便宜 |
| DeepSeek | 经相同验证后作为 L 开发候选；是否适合 H 由具体版本的实测和风险要求决定 | 实际服务端型号/版本、工具兼容、隐私、推理配置和当前价格；不把第三方转发服务等同官方版本 |
| Codex | 作为仓库操作、测试和 PR 的执行环境，承载经指定的 L 或 H 模型；H 可用于架构及独立审查 | **Codex 不是唯一模型 ID**；记录宿主实际模型/推理档位与权限，不把界面模型列表或配置文件视为已执行证据 |

选择时比较实际可用性、输入/输出及缓存计费、订阅/配额、延迟、有效上下文、代码正确性、工具权限和失败重做成本。优先复用已审查契约和小范围任务，避免重复加载无关历史；不能为了省上下文删去关键契约或测试证据。只核对当前官方说明、账户允许查看的账单/配置及项目实测，记录来源日期；本仓库不硬编码第三方价格、剩余额度或节省比例，也不自动调用任何模型服务。

## 4. 批次与独立 H 审查

默认把连续 **2—4 个 L TASK** 组成一个开发批次。批次负责人在任务单或项目状态登记批次 ID、每个 TASK 的执行模型、PR、冻结 SHA、测试证据、风险和待审状态；同时规划一个独立 H 审查 TASK。批次跨会话/分支持续累计，不能靠更名或新开批次清零尚未审查的 4 项上限；不足 2 项而阶段即将结束也安排审查。

L 交付可以先创建单独 PR 供人工处理，但不能将普通人工合并或 CI 绿灯冒充集中 H 审查。最多 4 个未被 H 结论覆盖的 L TASK，第 4 项后暂停新 L 实现，先完成集中审查；在此之前不得宣称相应阶段验收通过或进入生产使用。是否合并仍由用户决定，执行模型不自动合并。

**高风险实现由 H 承担，且必须另有独立 H 审查 TASK，在合并该高风险变更及阶段验收之前完成。** 不因配额不足、批次未满或实现模型已经是 H 而延后；无审查资源时保留 PR 并标记“等待审查”。本次治理制度也走这一机制。

独立审查至少满足：

1. 新 TASK 编号、单独执行会话/干净审查上下文、自己的唯一 H 模型/档位和明确只读范围；不得由当前实现会话换角色自称独立审查。同型号的新独立会话可承担审查，但必须披露，并不声称已做异模型交叉验证；若任务要求不同模型，则另行明确指定。
2. 绑定被审任务列表、冻结提交/文件树和测试基线；检查模块间契约、累计风险、失败路径、测试实际覆盖以及证据类型。不能只看模型总结或测试数量。
3. 审查 TASK 只提交问题和结论，不顺手修改被审实现。问题修复建立独立 TASK，完成后由原审查 TASK 对新 SHA 复核；审查 TASK 仍使用自己的固定模型/档位。
4. 结论写为通过、附条件、阻断或证据不足，逐项列严重程度、路径/行号、复现和验收条件。阻断/证据不足不能算批次通过；附条件项未关闭不得解除对应风险门禁。
5. 旧结论仅覆盖其 SHA 与范围；修复或后续改动有新 SHA 时说明差异并重新确认覆盖，不能沿用旧批准覆盖未审代码。远端自动模型审查若存在，也须登记为独立 review TASK，不能悄悄算入实现任务或充当未指派的正式审查。

## 5. 升级、失败与阻断

| 触发 | 当下动作 | 独立后续 TASK |
| --- | --- | --- |
| L 对同一验收项两次有不同诊断依据的修复仍失败，或达到任务预算/重试上限（以更早者为准） | 停止重复尝试，保留 diff/日志，说明两次尝试与剩余假设 | H 诊断/审查；修复按诊断结果另立任务 |
| 契约冲突、时间/未来函数问题、迁移/核心执行风险、核心测试失败 | **立即**停止扩大修改及依赖开发，不等待两次失败或批次结束 | H 架构/风险审查；必要实现另立 H TASK |
| 需要跨范围修改、新依赖、模型或推理档位变化 | 记录新需求与影响，不在原任务偷加 | 独立 scope/升级 TASK，重做模型与验收分配 |
| 模型/来源/网络/测试环境不可确认 | 保存可复现的脱敏证据；状态写环境阻断/未执行，不报通过 | 有明确目标的环境或来源验收 TASK；不能换模型或降 TLS/校验绕过 |

阻断报告至少包括：任务与模型、基线/依赖 SHA、失败命令/退出码/脱敏输出、预期/实际、受影响断言和文件、已尝试步骤、保存改动位置、最小解决方案及建议后续 TASK。重复失败按同一问题跨任务累计；重开编号不恢复新的重试预算。没有预算数值不能理解为无限尝试。

## 6. 可验证交付与执行边界

每次交付将以下证据分列，不互相替代：

| 验证类型 | 必须说明 |
| --- | --- |
| 离线测试 | 环境/依赖、隔离临时数据库、命令、退出码、通过/失败/跳过数和原因、输出位置 |
| 真实网络 | 显式开启、目标/参数/次数、时间、状态/错误分类、字段/行数/来源及时间证据；成功请求不等于完整数据验收 |
| 本地 UI 端到端 | 实际界面、操作路径、环境、网络及同一数据库读回证据；代码/CI 通过不代表用户界面验收 |
| 样本外回测 | 冻结训练/验证/样本外划分、规则和快照、成本/执行时点、实际输出；单元测试或样本内收益不代表样本外成立 |

使用“通过/失败/未执行/环境阻断”逐项记录，实施者声明与实际输出分别标注。禁止伪造数据或测试、改 expected 掩盖核心失败、关闭 TLS、无授权操作生产库/凭据、直接合并或部署。模型路由不能削弱 [DECISIONS](DECISIONS.md)、[数据契约](DATA_CONTRACT.md)、[接口契约](INTERFACE_CONTRACT.md)与[验收标准](ACCEPTANCE_TESTS.md)。

本制度通过任务单、PR 和独立审查落实，**本次没有新增 CI 检查器、模型锁、费用监控或分支保护配置**。后续如要自动化，单独立项并明确权限。新规则文件加入已有会话后应显式重读；新任务从仓库根目录开始，核对实际加载的全局/根目录/子目录/override 链，发现缺失或冲突先报告，不通过新增 override 绕过制度。

Codex 兼容性依据（2026-10-17 核对）：[官方 AGENTS.md 发现规则](https://learn.chatgpt.com/docs/agent-configuration/agents-md)说明根目录与更近目录/override 的发现及可能的长度限制；[官方配置说明](https://learn.chatgpt.com/docs/config-file/config-basic)提供模型及受支持推理配置。仓库 Markdown 不能证明当前运行时已选中某模型，也不代替宿主权限；本任务未修改用户/项目 Codex 配置或启动另一模型。
