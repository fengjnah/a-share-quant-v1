# 开源调研与设计采用制度

版本：1.0；新增决策：2026-10-18；用户在 TASK-018 执行期间明确要求落库。**本分支待独立 H 审查和用户合并后正式采用**。不追溯声称历史任务已经遵守本制度，也不把旧 TASK-REF-001 的本地报告视为已审通过。

目标：在开发前找到可复用的设计与接口模式，减少重复建设，同时保留许可证、数据时点、实现证据和拒绝理由。调研不是下载/复制源码的许可，不是数据商业使用授权，也不是业务验收通过。

## R01 适用性与开始记录

以下情况必须在实现前完成与风险相称的有界调研：新增业务模块/核心算法、引入或替换依赖/数据源、重要接口或架构决策变更，以及 Schema、历史时点、未来函数、回测执行和生产边界设计。

每个任务先检查已有实现、契约、调研报告及其固定提交；已有研究仍适用时，只补差异，不重复全面研究。开始报告必须填写“适用/复用既有研究/不适用”、理由、已读报告及 SHA、候选项目和停止条件。纯文字整理、本地 Git 现场保护、已定位的小修复或不改变契约的展示维护，可记录不适用及具体依据；不能用“低风险”三个字代替分析。

用户已明确指定参考项目、范围或预算时按用户要求执行。否则通常选择 2–3 个与问题直接相关的候选；扩大至更多候选前说明新增价值。任务单记录资料范围、时间/请求预算和停止条件；不无限搜索，也不为了凑项目数量引入依赖。

## R02 必须检查的实际证据

不能只读 README 或项目简介。对拟采用的设计至少检查：

1. README/架构说明、与问题相关的关键模块、边界接口、失败路径和对应测试。
2. 固定 commit/tag、实际文件路径、访问日期；若只看默认分支动态链接，标记未冻结，不冒充可复查快照。
3. 测试是实际执行、只读源码还是未运行；执行时记录环境、命令、退出码和数量，不因项目有测试目录就认定通过。
4. 真实接口、网络、覆盖/性能/可靠性若未实测，单独写“未验证”，不能由 mock、文档样例或社区经验推断。

只读访问遵守任务网络授权；不为调研偷偷调用真实行情/交易接口、扩大下载范围、关闭 TLS 或提交秘密/原始行情。引用只保留必要短摘录、链接、接口签名和设计概括，不复制大段实现。

## R03 能力对照与采用决定

按本任务相关能力制作对照表；证券/行情系统通常涉及采集、字段/单位、数据契约、SQLite/迁移、历史版本、日历/复权、选股、回测、费用滑点、风控和报告。每项标记“本项目已有/缺失/设计不足/需要进一步验证”，附本项目路径/提交和参考源码或测试依据。

每个建议必须选择：**采用设计思想 / 适配接口模式 / 拒绝 / 延后验证**，说明与现有 ADR/契约的兼容性、最小改动、失败处理、验收方法及剩余风险。不能仅因参考项目功能多就建议整体引入；不能重复实现仓库已有 SQLite/版本链或借参考设计改变 as_of。

## R04 软件许可证与数据授权分开核实

拟直接引入代码/依赖前，实际读取对应版本 LICENSE/COPYING、相关子模块和必要依赖的许可证/例外条款，记录路径、提交、许可证标识及未确认项。对传递依赖先列明本次会触达的范围，无法确认的部分保持未知，不声称已完成全量许可审计。

特别关注 RQAlpha 的非商业使用限制议题和 Backtrader 的 GPL-3.0 议题，均须按**实际版本文件**核实，不能把历史结论套用到未来版本、插件或分发方式。本制度本次没有重新核验这些项目的当前许可证。

软件开源许可不等于供应商数据许可。分别记录个人研究、本地存储、自动采集、商业使用、对外展示和再分发是否获准及证据。区分免费可获取、可能需授权、无法公开准确推断的信息；不能把机构代理指标称作真实机构持仓。

许可证/授权未知时，可以提交设计层研究及缺口报告；不得据此推荐直接复制源码、生产接入或公开分发。需要授权解释或法律判断的事项列为待核实，不由执行模型自行宣称获准。

## R05 量化系统的专项风险

涉及相关模块时，调研必须单列：财务报告期与实际发布时间/修订、历史成分及实体身份、复权因子版本/原始口径、停牌/涨跌停、信号可得时间与成交时点、费用滑点和数据缺失语义。

不得把下载时刻冒充历史首发、把当前名称/成分/ST 倒填历史、把缺少日历当休市、把未知当可交易、把 SDK 帧当原始复权键证据。与 [DATA_CONTRACT](DATA_CONTRACT.md)、[INTERFACE_CONTRACT](INTERFACE_CONTRACT.md) 或 [DECISIONS](DECISIONS.md) 冲突时先停止相关实现，记录最小问题及影响，另行审查，不悄悄迁就参考项目。

## R06 交付记录模板

可在 `docs/research/<TASK-ID>.md` 或相应实施报告中记录，不要求本任务创建虚假的历史研究报告。最小记录如下：

| 字段 | 必填内容 |
| --- | --- |
| 任务/适用性 | TASK、目标/非目标、触发条件或不适用理由 |
| 模型与预算 | 一个实际执行模型/档位、核验来源、范围/停止条件；费用未知则写未知 |
| 本项目基线 | main/任务 SHA、相关代码/契约、已有研究及差异 |
| 候选与阅读 | 项目、固定版本、README/架构、实际模块/测试路径与链接、未读项 |
| 能力矩阵 | 已有/缺失/不足/待验证，逐项证据及限制 |
| 许可证 | 主项目/相关依赖实际许可文件及版本，未确认项 |
| 数据边界 | 来源/字段/单位/覆盖/可得时间/授权；免费不等于可再分发 |
| 未来函数 | 适用风险、现有保护、缺口与必须验证的反例 |
| 采用决定 | 设计/接口/拒绝/延后，理由、最小范围、测试和独立审查门槛 |
| 实际验证 | 代码阅读/离线/真实网络/UI/样本外分列，命令/输出及未执行项 |
| 后续 | 阻塞、任务依赖、审查 SHA、是否允许实现；建议不等于任务已创建 |

## R07 路由、审查与看板

遵循 [MODEL_ROUTING_POLICY](MODEL_ROUTING_POLICY.md) 和根 AGENTS：一个 TASK 固定一个模型/档位。低风险资料整理可建议 Agnes 3.0 Flash，但开始前必须核实实际型号、工具/网络可用性，不能靠品牌推断成本或能力。架构、迁移、时点、未来函数、回测和来源/许可边界由已指定的 H 模型制定规则或独立审查。

实现者的调研、自检和 CI 不等于独立审查；高风险设计/采用决定在独立 H 审查通过前不能解除合并或阶段验收门禁。GitHub 基线/PR 操作使用可靠可访问环境，不因某模型无法联网就采用旧缓存或跳过证据。

任务结束将调研产物、真实验收状态、阻塞及下一项条件写入 [TASK_BOARD](TASK_BOARD.md) 对应的结构化反馈；保持旧记录，未知计零。仅“报告已创建”不等于“调研通过”，更不等于代码、真实数据或生产准入通过。

## R08 维护与本次边界

接口/依赖版本、许可证、来源覆盖或关键契约变化时，按差异重新核实；旧结论只覆盖其固定 SHA 和范围。没有自动爬取、定时调研或未经用户授权的提醒/通知服务。

本次仅新增制度、任务模板/根规则入口和管理看板引用，**未运行新的外部项目调研、许可证审计或真实数据验收**。原 TASK-REF-001 研究材料仍按 TASK-016 的未跟踪/待审状态保留。本制度和 TASK-018 应一起交给独立 H 审查，用户合并前保持待审，不在当前实现会话换角色宣称正式审查完成。
