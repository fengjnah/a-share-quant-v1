# 分阶段实施计划

## 原则

先建立可重放的数据事实，再实现特征与策略；先验证可得性和执行约束，再比较收益。每个任务产生小而可审阅的提交，配置、迁移和测试与功能同一变更提交。P0 不包含真实交易、自动下单、云端计算或付费服务引入。

## P0：审计型数据与回测骨架

**目标：** 让一条最小日频策略可以在合成数据上被无未来函数地回放，并能生成不可误导的本地日报产物。

| 顺序 | 工作包 | 产出 | 依赖与完成条件 |
| --- | --- | --- | --- |
| P0-0 | 工程基线 | README、目录规范、配置样例、格式/测试命令、CI 最小检查 | 文档决策已确认；不加入业务逻辑 |
| P0-1 | 领域模型与 SQLite 迁移 | 元数据字段、原始归档索引、主数据/日历/行情/公司行为核心表 | 契约评审；迁移可重复，约束阻止缺失时间字段 |
| P0-2 | 统一数据访问 | `DataAccess`、严格/研究模式、快照与血缘查询 | P0-1；通过 AT-001、002、011 |
| P0-3 | 基础采集适配器 | 可替换的来源适配器、载荷归档、标准化和质量报告 | P0-1/2；合成源及幂等测试通过 AT-012 |
| P0-4 | 日历、证券主数据、可交易性 | 历史状态、停牌/涨跌停、会话查询 | P0-1/2；通过 AT-007 至 009 |
| P0-5 | 复权与成本/执行模拟 | 因子版本、订单状态机、费用/滑点模型 | P0-4；通过 AT-003、010、018 |
| P0-6 | 特征与信号时间骨架 | 日/周特征输入、`earliest_execution_session` | P0-2/4；通过 AT-004、005 |
| P0-7 | 最小回测与审计报告 | 可复现组合记账、订单/成交/净值/manifest | P0-5/6；通过 AT-019 |
| P0-8 | 日报构建与静态发布边界 | 本地 HTML/JSON、manifest、发布白名单验证 | P0-7；通过 AT-020 至 022，不部署 AWS |

P0 的策略仅可使用合成或已明确可得性的少量历史数据做验证；不承诺股票推荐质量，不接入真实账户，不运行生产定时任务。

## P1：研究能力与策略规则

1. 接入经许可和字段审查的历史日线、交易日历、证券状态、公司行为与财务公告；建立数据质量仪表盘。
2. 实现历史指数/行业/概念成分，板块广度与市场状态；补齐 AT-006、013、014。
3. 将非 ST、可交易、历史可得市值不少于 100 亿元做成版本化股票池；在业务方确认后实现热门板块、行业龙头、成长性与评分解释。
4. 实现日线/周线择时、止损、仓位与集中度控制；研究空仓与始终持仓的公平对照。
5. 接入经可得性验证的全球风险代理与公开期货会员字段；完成 AT-015 至 017。
6. 通过人工审查后建立本地定时采集/日报构建，并将静态产物发布到已配置的 Nginx。

## P2：扩展、运营与性能

1. 在相同契约下增加 Parquet/DuckDB 读取路径，针对大规模横截面研究优化，但以 SQLite 审计快照为准。
2. 引入更完整的公告、财务修订、公司行为、成交容量和流动性模型；进行 walk-forward、子样本、敏感性和数据修订影响分析。
3. 完善发布的 HTTPS、认证、审计日志、监控、回滚和保留策略；评估静态站点替代 EC2 的成本。
4. 只有独立的风控、合规、故障演练和人工审批流程成熟后，才讨论与券商模拟环境的隔离集成；真实交易不属于当前路线图承诺。

## 任务拆分与审查责任

| 角色/审查点 | 关注内容 |
| --- | --- |
| 数据工程审查 | 来源许可、字段映射、时间戳、版本、原始载荷与质量阈值 |
| 量化研究审查 | 因子定义、样本内外、幸存者偏差、市场状态及公平基准 |
| 回测审计审查 | `as_of`、可成交性、成本、复权、公司行为、可复现性 |
| 安全/运维审查 | 凭据边界、静态发布白名单、日志、HTTPS、访问控制与回滚 |
| 业务审查 | 股票池和评分语义、日报可读性、风险披露与不构成建议说明 |

## 进入下一阶段的条件

P0 文档须经人工确认其中的 Q-001 至 Q-010。随后按 P0-0 至 P0-8 顺序实现，每个工作包仅在其验收测试通过、审计元数据完整且不扩大真实交易边界时进入下一项。P1 任何接入真实历史源的任务，都必须先新增来源适配器的字段映射、许可记录、可得性规则与合成回归测试。
