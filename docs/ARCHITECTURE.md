# A股量化交易系统 V1.3 架构

## 目标与边界

系统服务于 A 股日频/周频研究：本地 PC 获取公开数据，保存可审计历史，计算市场状态、选股、择时、风险控制和对照回测，并生成每日精选 3--5 只股票和指定标的分析。它不是交易执行系统，也不保证收益。

V1.3 的默认数据引擎是 SQLite。所有业务模块仅依赖统一数据访问接口，不直接依赖 SQLite SQL；因此可在后续版本以同一领域模型接入 Parquet/DuckDB。AKShare 是候选采集适配器而不是领域模型的一部分，必须隔离其字段名称、接口变化和失败方式。

## 分层与数据流

```text
外部公开源
  -> [行情采集 | 证券主数据 | 交易日历 | 公告/财务 | 复权因子 | 全球风险 | 公开期货排名]
  -> 原始载荷归档 + 标准化验证
  -> DataAccess（SQLite 默认实现；Parquet/DuckDB 预留实现）
  -> [市场状态 | 板块分析 | 指标/特征]
  -> [股票池过滤 -> 选股评分 -> 入场择时 -> 风险控制]
  -> 回测编排器（交易成本、可交易性、组合记账、审计输出）
  -> 日报构建器（HTML/JSON 静态产物）
  -> 本地人工审阅/同步
  -> AWS Nginx 静态只读发布 -> 手机浏览器
```

箭头代表数据依赖，不代表可以绕过可得时间检查。任何研究或回测查询都必须传入 `as_of`；数据访问层只返回 `available_at <= as_of` 的版本。研究模式允许显式标识为非审计数据，交易/严谨回测模式不允许此类放宽。

## 模块职责

| 模块 | 职责 | 关键输出 | 不负责 |
| --- | --- | --- | --- |
| `market_data` | 日线/分钟外数据的采集、原始归档、标准化 | 版本化 OHLCV、停牌/涨跌停状态 | 指标和交易信号 |
| `trading_calendar` | 交易日、开收盘、假期、调休 | 市场会话与下一交易日 | 用自然日猜测交易日 |
| `security_master` | 代码、简称、上市/退市、证券类型、ST 历史 | 历史证券身份和状态 | 把当前名称投射到历史 |
| `corporate_actions` | 除权除息、复权因子及版本 | 价格调整序列 | 默认替换原始价格 |
| `storage` / `data_access` | 写入、版本、可得性过滤、血缘查询 | 领域查询接口 | 策略判定 |
| `market_regime` | 全 A 等权等市场宽度与连续普跌恢复规则 | 可得时点的市场状态 | 个股推荐 |
| `global_risk` | 明确代理的外围风险序列和缺失处理 | 风险门控输入与证据等级 | 声称预测全球市场 |
| `sector_analysis` | 行业/概念映射历史、强弱、广度 | 板块特征 | 使用当前成分回填历史 |
| `selection` | 股票池、成长/龙头/热度特征、评分及解释 | 候选排序和证据 | 下单 |
| `timing` | 日/周线入场与退出信号 | 有效期和最早成交会话 | 用未完成周的周收盘 |
| `risk` | 仓位、集中度、止损、风险门控 | 目标持仓约束 | 改写原始信号历史 |
| `backtest` | 事件驱动回放、订单模拟、组合记账和报告 | 审计回测结果 | 调用真实账户 |
| `daily_report` | 固化某一 `as_of` 的 HTML/JSON | 发布目录及 manifest | 在线计算全市场 |
| `publisher` | 将已验证静态目录传至发布目标 | 发布版本与校验 | EC2 上构建报告 |

## 本地与 AWS 责任划分

| 工作负载 | 本地 PC | AWS EC2 t3.micro |
| --- | --- | --- |
| 数据采集、清洗、归档 | 是 | 否 |
| SQLite、全市场指标、策略研究、回测 | 是 | 否 |
| 日报 HTML/JSON 构建、完整性校验 | 是 | 否 |
| 仅静态日报文件托管 | 可预览 | 是，Nginx |
| 数据源密钥、交易凭据 | 本地受保护配置；P0 不使用交易凭据 | 禁止 |
| 计算任务/定时回测 | 本地计划任务（后续） | 禁止 |

发布目录只含静态页面、JSON、资源与 `manifest.json`（构建时间、`as_of`、代码版本、数据截点、内容哈希）。Nginx 关闭目录浏览；传输、认证、保留期限和手机端访问方式待确认。云端不得持有全量历史数据库。

## 核心时序

日频收盘信号的默认保守约定：交易日 `D` 的完整日线在 `D` 收盘及供应商延迟后才可用；以该数据生成的信号，最早在 `next_session(D)` 的可成交窗口执行。若配置在当日某时点运行，必须使用明确的 `as_of`，不得把事后补全的日线视为已知。

周频信号仅在本周最后一个交易日收盘且数据可用后生成，最早于下一交易周第一个可交易会话执行。财务、公告、指数成分和板块映射同样使用各自 `available_at`，而非业务期间或当前网页显示日期。

## 可扩展存储

SQLite 作为权威写入库，适合单机、小并发、可迁移的 P0。接口将查询分为：实体查询、时间序列查询、横截面快照、血缘查询和产物查询。未来 Parquet/DuckDB 实现可以优化批量研究读取，但不得改变字段语义、主键、版本选择、空值和时区语义。
