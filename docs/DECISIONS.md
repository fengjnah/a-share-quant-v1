# 架构决策与待确认事项

## 已采纳决策

### ADR-001：V1.3 默认 SQLite，数据访问接口独立

**状态：接受。** 本地单机、低成本、部署简单的目标适合 SQLite。所有模块经 `DataAccess` 读取，未来可加 Parquet/DuckDB 实现。SQLite 是权威事实与审计库，不代表全量研究永远只使用 SQLite。

### ADR-002：采用可得时间驱动的双时间查询

**状态：接受。** 每条记录强制 `source`、`event_time`、`available_at`、`ingested_at`；严格回测按 `as_of` 过滤。代价是采集、版本和测试更复杂，收益是能审计并阻断常见未来函数。

### ADR-003：本地计算，AWS 静态发布

**状态：接受。** PC 完成采集、SQLite、回测与日报构建；EC2 t3.micro 只用 Nginx 服务已验证的静态 HTML/JSON。不在服务器运行任务队列、全市场计算、数据库或交易连接，以控制成本与攻击面。

### ADR-004：原始行情与复权行情双存，成交基于可交易规则

**状态：接受。** 原始行情不可覆盖；复权序列为有版本的派生数据。信号可用明确的复权口径，模拟成交必须考虑未复权价格、公司行为、停牌、涨跌停和成本。

### ADR-005：机构信息按可验证性分级

**状态：接受。** 对可复查的交易所公开会员数据可做 A 级事实展示；公开数据计算出的代理为 B 级；无法确认最终机构主体的一律 C 级且不纳入“机构净持仓”。详见 [DATA_CONTRACT.md](DATA_CONTRACT.md)。

### ADR-006：回测比较统一执行条件

**状态：接受。** `cash_capable` 与 `always_invested` 只能在同一数据快照、股票池、下单时点、成本、滑点和再平衡规则下比较。差异仅限明确定义的暴露/空仓规则。
